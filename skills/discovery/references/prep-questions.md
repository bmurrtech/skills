# Prep questions

Use for **prep**. Output two blocks, both tagged `[K]` `[P]` `[F]` `[S]`:

1. **Need-to-know**: the signals to capture in the room or in follow-up comms.
   One line each. Open gaps from existing briefs come first, most blocking first.
2. **Questions**: honed from the catalog below to this engagement's words.

Done when every dimension has at least one line, or is marked "already evidenced".

## Shape

```text
Need-to-know: <engagement>
- [P] <who feels it, how often, consequence>
- [K] <measure that should move + today's baseline>
- [F] <weakest area for a first demo; can sample/static data stand in?>
- [S] <who wants it; who signs off a pilot>

Questions
1. [P] …
```

## Catalog

Lead with pain. Drop anything earlier materials already answer.

**Pain [P]**
- Walk me through the last time this went badly. Who did what, in what order?
- Where does the work stall, loop back, or get redone?
- How often does that happen, and who pays for it?

**Impact [K]**
- If this were fixed, which number would you watch: hours, turnaround, errors, cost?
- Roughly what is that number today?
- If money is involved, is it a budget cut, avoided spend, or freed-up time?

**Feasibility [F]**
- Which systems or files does this work touch today? (names only)
- Is the data it needs already cleared for this kind of use?
- Could a first demo run on a sample or export instead of a live connection?
- Who controls access to those systems and the rules behind them?
- What must this never touch?
- Is there a tool that almost does this? What is the one missing piece?

**Sentiment [S]**
- If you could start only one thing with us, is it this one?
- Who would sponsor a pilot with time, sample data, or a sign-off, and are they on board?

**Shortlisting** (several candidates on the table; stop once the room converges and note which framing settled it)
- Which one gives the organization the most back?
- Which one improves the most people's day?
- Which one is safe enough to win trust for the rest?
- Is each one for people outside the team (external) or for the team's own work (internal)?

**Toward a pilot** (only for top-ranked use cases)
- What does "good enough" look like, and what miss is unacceptable?
- What starts the workflow: an event, a person, a file, a schedule?
- Which integrations are required for the pilot to be real, and which can wait?

## Hone from context

| You already have… | Do |
|---|---|
| Named systems | Ask how each fits the broken step; skip "what do you use?" |
| A proposed solution | Ask what work it replaces and where that work fails |
| Existing briefs | Ask only their open gaps |
| A sensitive domain | Ask about data approval and boundaries early |

## Never ask in prep

Hosting, runtime, auth design, architecture diagrams, MoSCoW, NFR measurement
methods, lead developer, charter dates. These belong to design and intake, after discovery.
