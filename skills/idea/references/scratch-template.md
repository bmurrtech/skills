# Scratch idea template

Use under `.scratch/ideas/<kebab-slug>.md`. Internal, detailed, recoverable.
Promote via **`roadmap`** into the leaner public shape in
[roadmap-template.md](../../roadmap/references/roadmap-template.md).

**Preserve first.** Fill structured sections when obvious; leave blank or omit
when not. Do not questionnaire the user at capture time.

```markdown
# <Working title>

## Idea

<Raw brain dump. Fragments, incomplete thoughts, examples, questions,
references, copied prompts, and contradictory ideas are all acceptable.>

## Domain

`<area / subsystem / skill / integration>`

## Intent

<Why this exists; outcome sought. Can stay rough.>

## Scope

- <capability or behavior implied>
- <relationship to existing systems>

## Boundaries

- <non-goal or ownership distinction>
- <what this should not become>

## Constraints

- <architectural, compatibility, security, performance, context, dependency, or operational>
- <dev-only constraints and caveats OK here>

## Open Questions

- <unresolved decision or uncertainty>

## Interfaces

- Scratch: `.scratch/ideas/<this-file>.md`
- GitHub: `<issue / discussion / PR or none>`
- Fizzy: `<card / board or none>`
- PRD / handoff: `<related artifact or none>`
- Knowledge: `<related durable knowledge or none>`

## Notes

<Important context, examples, reasoning, session triggers.>

## Context

<Optional internal: why this came up, what triggered the thought.>

## References

<Optional internal: files, symbols, URLs, skills, PRDs, handoffs, pasted prompts.>

## Dev notes

<Optional internal: implementation hunches, spike ideas, “try X later” — usually
dropped or condensed on promote unless it is a real constraint.>
```

Field names above match the public roadmap entry so promotion is classification
into a shorter public form, not a rename exercise.
